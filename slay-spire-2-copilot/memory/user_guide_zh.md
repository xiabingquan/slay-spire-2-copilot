# User guide（用户指南）

用户撰写的记忆实践指南——记录对局记忆（run memory）时查阅本文件。

## 记录记忆时要覆盖什么

从这些方面入手——每一类对应 lessons/ 下的一个分类文件：

- 角色特质 → `memory/lessons/characters.md`
- 卡牌特质 → `memory/lessons/cards.md`
- 遗物特质 → `memory/lessons/relics.md`
- 跨元素协同（卡×卡、卡×遗物……）→ `memory/lessons/synergies.md`
- 敌人教条、事件、经济、战斗原则 → 对应的 lessons 文件

特别关注元素之间的交互——此类协同可以让整套牌组变得极强，是记录的重点。

机制事实（卡/遗物/敌人**是什么、怎么算**）存于程序化存储
`bridge/spirectl_lib/data/`：任何 id 用 `spirectl lookup <id>` 解析——
该存储只含结构化字段（schema 见 `bridge/spirectl_lib/schema.py`，codex
为权威结构源）。教条、用法笔记等散文绝不进数据存储，归 lessons。

## 回顾时的信息意识

信息类问题按性质分流——它不是 run 笔记里的独立维度：

- state 中信息真正缺失/不明 → skill/mod/data 缺陷：当场在对应系统修复；
  绝不作为 run factor 记录
- 信息可用但未被使用（data/lookup、state 字段、档案笔记）→ 按失败性质
  归类：
  - 过程：纪律违规——战前 lookup 没做、行动前未重读 state（进 run 笔记
    What went poorly 表，类型 = 过程）
  - 决策：信息未核实即行动（类型 = 决策）
- 结构化事实一律先 lookup 解析；lookup miss 是研究触发器——把 codex
  结构折入 data（schema 严格）——不是猜测许可

## 积累有益经验

对局记忆的核心目标是积累支撑后续决策的经验。笔记格式由
`memory/template.md` 固定：What went well / What went poorly / Key moments
均为表格——`# | [时机 |] 类型 | 内容 | 代价/收益 | 下次参考`——每表最多
7 行；超出只 drop 弱行，禁止合并行。类型格只能用共享枚举：

- 决策 —— 路线、商店买卖、战内选择、药水时机（含信息未核实即行动）
- 卡牌 —— 单卡的抓取与打出表现
- 遗物 —— 遗物获取与其价值兑现
- 构筑 —— 牌组/引擎形状与协同（卡×遗物×角色），含对已知机制的牌组准备度
- 过程 —— 执行纪律与工具过程（单卡每次、全量重读、fail-loud、SL 使用；
  含在手信息未按纪律使用）
- 客观 —— 非决策因素：抽牌、掉落、地图几何、经济运气

「What went well」记录值得复用的发挥与结果——优先有前向参考价值的，
而非例行的好结果；代价/收益列填收益。
「What went poorly」记录决策级反思与客观损失；代价/收益列填代价，
下次参考列写给下一局的一句建议。

## 决策与客观因素

两张表都覆盖决策与客观因素——客观的正面（如全程抽牌顺）进 well，
客观的负面（如遗物供给差）进 poorly；每行按共享枚举归类
（决策 / 客观 / 其余按内容定）。

## 各角色核心玩法

角色层面积累住在 `memory/lessons/characters.md`——每个角色一个一级
标题；经验以无序列表写在各标题下：取胜方式、该角色想要的关键遗物/卡、
构建脊线。run 笔记不承载这些常备知识——lessons 是它们的家。

## Summary 内容

每局笔记的 Summary 节中，除核心事实表外，恰好写两条列表项，覆盖本局
最大的收获与最大的损失：

- 本局唯一最大的收获
- 本局唯一最大的损失

事实表本身的格式（含 Date 行）定义在 `memory/template.md`。

## Overview 表格规则

每一局都必须同步记录进 `memory/overview.md`，规则如下：

- 列顺序：**对局序号** | 角色 | 日期 | **进阶** | 到达楼层 | 胜负 | SL 次数 | 备注
- **对局序号**按时间顺序从 1 开始编号；最新一局位于表格**最顶部**，序号最大
- **进阶**列只写**裸数字**（0、1、2…）——该局实际打出的进阶难度
- **最新一局放在表格顶部**（倒序排列）；追加新局时把行**插入表格顶部**，禁止插到底部
- **备注**格保持 meta：一行结局/死因。叙事与教训写入该局的 `memory/runs/` 笔记，或 `# 阶段性反思` 节——绝不写进表格格子
- 备注只写最简单的信息，范例：`Act3 全清 → 到达建筑师（本存档首次 Act3 通关）`、`死于 Act2 Boss 知识恶魔（剩 91/379）`
- run note 的 Summary 表、记忆备注与 overview 行中记录的进阶数必须三处一致

## 阶段性反思

`memory/overview.md` 顶层带有一个 `# 阶段性反思` 节；每次反思是其下的一个 `## 反思 (yyyy-mm-dd)` 子节。

- **第一次反思**：覆盖当时为止已记录的**全部**对局
- **此后每次反思**：覆盖自上次以来的 20 局（第二次覆盖 36–55，第三次 56–75，……）——累计对局数到达该边界时触发
- 素材：`memory/runs/` 下覆盖区间内的对局笔记——先读笔记，再以结构化形式（markdown 表格、有序/无序列表）反思得失
- 这是 overview.md 中**唯一**允许出现教训的地方

## SL 次数

每局笔记都应记录该局的 SL（save/load）次数——该局中途通过 `continue_run` / 重启游戏恢复的次数（游戏进程全程未断则为 0）。**两处都要记录**：

- run note 的 Summary 表（`SL count` 字段）——次数 > 0 时另加一行说明 SL 了什么、为什么
- overview.md 表格中该局所在行的 `SL 次数` 列

计数规则：游戏进程中断后每次 `continue_run` = +1；新开 `start_run` 重新计数。该规则出台之前记录的对局，overview 格子填 `未记录`，除非记忆笔记中已载明该数字。

## 何时查阅记忆

记忆贯穿整个游玩过程——它是游戏的常备参考，不只是开局时的一次性动作：

- **会话/开局强制项：只读 `overview.md`**——表格、统计与阶段性反思构成跨局全景；单局完整笔记开局时一般**不需要**
- **`lessons/` 是常备经验层**——局中决策受益时随时查阅：敌人教条
  （lessons/enemies.md）、协同（lessons/synergies.md）、角色脊线
  （lessons/characters.md）等；机制数值仍先用 `spirectl lookup <id>` 解析
- **按需查阅**：要读某一局的完整记录时，打开那一份笔记——文件名带对局序号前缀（`0051_IRONCLAD_...`），与 overview.md 的对局序号列对应；先查号再开文件
- 游玩过程中任何时候：当某个决策会受益于历史记录时，查阅具体的对局笔记或角色积累

## 经验是建议性的，不是硬性模式

记录对局记忆时，把面向未来对局的经验写成**建议 / 参考观察**，而不是有约束力的硬性模式：

- 措辞：优先用「建议… / 参考… / run-X observed…」，避免「强烈建议 / 强烈建议不要」
- **所有过去对局仅供参考。**局内具体措施必须依据**当前局的 live 状态**（HP、牌组、手牌、敌人、地图几何）来定，不从旧笔记或 lessons 整体照搬
- 过去经验只是决策的输入之一；live 情况永远优先
- 局中查阅记忆时同样如此：把旧笔记与 lessons 当数据读，然后适配——不要照搬另一局的剧本

## 阶段性反思必须覆盖高频死亡敌人

`memory/overview.md` 的阶段性反思节中，除既有的得失分析外：

- 识别覆盖区间内的**高频失败敌人**（击杀过多局的敌人）
- 对每个敌人：总结死亡的**根因**（机制误解？入场 HP 数学？抽牌/牌组问题？过程债？）
- 推演**对策**——以建议性口吻写给未来对局（非硬性模式），按 live 情况适配；沉淀为常备结论的部分进入 `memory/lessons/enemies.md`

## 记忆只保留前向价值内容

对局笔记与 overview 的总原则：**只记录对未来对局有参考价值的内容**。

- **删除复仇式叙事**（「run-X 杀手已被击杀」、复仇条目）——击败曾经的杀局敌人没有前向参考价值
- **删除 mod 修复/过程重载叙事**（版本号、重建、工具缺陷重载过程）——工程日志，不是游玩参考
- overview 表备注与反思同一标准——只留前向有价值的事实
- 存活下来的内容：已验证机制（作为结构化事实存于 spirectl_lib/data，lookup 解析）、成本/HP 经济数据、协同、决策质量观察、建议性提示——后几类归 lessons 与 run 笔记表格

## 面向未来的游玩原则

给未来对局的建议性原则——每局按 live 情况适配：

- **HP 是首要资源，其优先价值随回合/阶段变化。**把 HP 当作最稀缺的货币，其兑换率随战斗变化：前期/低威胁回合 HP 花得起；刀尖回合与 Boss 税窗口里它无价。每一笔 HP 支出都要对照该回合换来什么（建议性——live 血线、incoming 意图与剩余战斗长度决定每回合的兑换率）。
- **战斗前期：引擎上线是第一优先。**战斗开局几回合，把 power/引擎装到位（Inferno、Vicious、毒、Inflame 类、挡引擎）优先于边际伤害或小幅度省血——引擎在整个战斗里复利滚动，早期蹭伤不会。花早期 HP 换引擎件落地常常是正确交易；具体数额永远是 live 判断。
